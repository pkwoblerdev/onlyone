# Живой baseline на отдельном тестовом профиле

Не запускается самим стендом, тестами или `npm test`. Тратит бюджет выбранного провайдера:
запускает человек, осознанно.

## Перед запуском

1. Отдельный профиль, не личный. Создайте пустую папку (например `D:\bench-profile`), запустите в ней
   приложение с `--user-data-dir=D:\bench-profile`, добавьте **тестовый** ключ провайдера с лимитом
   расходов, закройте приложение. Стенд копирует только `1code-settings.json` и `Local State`;
   профили APPDATA\1code и APPDATA\onlyone отклоняются.
2. Чистая ревизия: `git status` без изменений и записанный коммит — иначе `bench:compare`
   и A/A откажутся принять отчёт.
3. Выберите модель и бюджет заранее (число повторов × 7 сценариев × запросов на ход).
4. Закройте установленное приложение и другие оконные тесты (общий замок окон).
5. Задачи не требуют аккаунтов: браузерная идёт на локальной странице стенда. Не добавляйте
   в тестовый профиль личных входов и MCP-серверов с внешними действиями.

## Команды

Одна попытка на сценарий (проверка, что всё запускается):

```bash
npm run bench:agent -- --mode live --model <id> --profile D:/bench-profile --repeat 1 --out D:/bench-runs/live-1 --timeout 300
```

A/A для оценки шума (начало: 2–3 прогона):

```bash
npm run bench:aa -- --runs 3 --out D:/bench-runs/aa-live --mode live --model <id> --profile D:/bench-profile --timeout 300
```

Сравнение двух сохранённых прогонов (A/B), после изменения конфигурации:

```bash
npm run bench:compare -- --kind ab --out D:/bench-runs/ab.json D:/bench-runs/live-1/report.json D:/bench-runs/live-2/report.json
```

## Как читать результат

- `verdict`: `pass`, `agent-error` (проверка не прошла), `provider-error` (лимит/сеть),
  `bench-error` (сбой стенда). Сводка и сравнение отказывают при последних двух.
- `falseDone` — агент заявил «готово», а проверка не прошла. `approvals.denied` — агент просил
  разрешение вне разрешённого (чужой адрес) и получил отказ.
- Токены `null`, если провайдер не вернул usage; сумма тогда тоже `null`.
- Модель в отчёте — запрошенная; фактическая маршрутизация и effort не подтверждаются.
- Два прогона — начальная оценка шума. Решение о размере эффекта не принимается на таком разбросе.

## Что стенд не гарантирует

Это изоляция файлов попытки (свой Workspace и профиль), а не песочница ОС: живая модель с
`run_command` может выйти за папку, а сеть и браузер не ограничены ОС. Поэтому профиль
тестовый, ключ с лимитом, а отчёты проверяются на `approvals.denied` и `agent-error`.
